# CineScope

CineScope is a local movie-intelligence application built around the project's original `ASSETS\movie_metadata.csv` dataset and `ASSETS\BIA_CAPSTONE.ipynb` notebook. It provides dataset browsing, exploratory charts, the saved model comparison, a Random Forest prediction form, a movie archive, and a methodology guide.

The target is **IMDb-score-derived category**, not box-office success:

- Flop: `0 <= imdb_score < 3`
- Average: `3 <= imdb_score < 6`
- Hit: `6 <= imdb_score < 10`

The source notebook's detailed Random Forest report has 0% recall for Flop. The comparison page identifies the saved notebook values separately from evaluation generated by the deployable artifact.

## Technology

- Frontend: React, TypeScript, Vite, Tailwind CSS, React Router, Recharts, Lucide React
- Backend: FastAPI, Pandas, NumPy, scikit-learn, Joblib
- Data: existing CSV; no database required

## Architecture

```text
frontend/  React pages, typed API client, responsive design
backend/  FastAPI endpoints, data/analytics services, model export, tests
ASSETS/   Existing notebook and CSV (kept in place)
```

The API reads the existing CSV once and caches it for the process. Dataset/analytics routes compute from the actual source file. Notebook model-comparison values are preserved as saved notebook evidence. The deployable Random Forest uses 10 movie inputs: director name, runtime, genre, three actor names, budget, release year, language, and country. Facebook-like counts and color are deliberately excluded. The prediction form suggests director and actor names from the dataset as the user types. `backend\app\export_model.py` trains this model and compares it with the previous deployed model on the same held-out movies. Rare names are grouped during training; unseen names are ignored by the fitted encoder. Random splitting can put people in both train and test, so results may overstate generalization to entirely unseen people. Predictions never fit preprocessing on user input and fail explicitly if the artifact is missing.

## Windows setup

Use Python 3.13 (recommended) or Python 3.11+. Keep the existing notebook environment unchanged; use a separate virtual environment for the API.

From the project root, create a separate environment under your local Windows application data directory. This keeps notebook dependencies untouched and avoids writing Python wheels into the workspace:

```powershell
$BackendEnv = Join-Path $env:LOCALAPPDATA "cinescope-backend-env"
py -3.13 -m venv --system-site-packages $BackendEnv
& "$BackendEnv\Scripts\Activate.ps1"
python -m pip install --upgrade pip
python -m pip install -r backend\requirements.txt
```

Export and verify the Random Forest artifact once:

```powershell
Set-Location backend
python -m app.export_model
python -m pytest
```

Start the backend from `backend\`:

```powershell
python -m uvicorn app.main:app --reload
```

Install and start the frontend in a second PowerShell terminal:

```powershell
Set-Location frontend
if (-not (Get-Command npm -ErrorAction SilentlyContinue)) { $env:PATH = "E:\;" + $env:PATH }
npm install
npm run dev
```

Open the Vite URL printed in the terminal (normally `http://127.0.0.1:5173`). The API is served at `http://127.0.0.1:8000`; interactive API documentation is at `http://127.0.0.1:8000/docs`.

Optional environment settings can be copied from `backend\.env.example` and `frontend\.env.example`. `CINESCOPE_DATASET` and `CINESCOPE_ARTIFACT_DIR` override backend paths; `VITE_API_BASE_URL` sets the frontend API base URL.

## Dataset and model

- Dataset: `ASSETS\movie_metadata.csv` (5,043 raw rows, 28 columns)
- Notebook: `ASSETS\BIA_CAPSTONE.ipynb`
- Generated model artifact: `backend\artifacts\random_forest_pipeline.joblib`
- Generated evaluation metadata: `backend\artifacts\model_metadata.json`

The artifact files are produced locally and are not committed by default; run `python -m app.export_model` after updating the feature schema to rebuild them. Do not load model artifacts from untrusted sources. scikit-learn serialization is version-sensitive.

## Known limitations

- The cleaned dataset has 4,998 rows, including only 41 Flops; the saved notebook holdout has 8 Flop examples.
- The notebook and site use the same reduced-input Random Forest holdout metrics: 74.6% accuracy, 45.69% macro precision, 45.83% balanced accuracy, and 45.76% macro F1. The earlier full-feature notebook Random Forest scored 76.2% accuracy, but used different inputs and is not the deployed model. High accuracy does not imply useful minority-class detection.
- The reduced-input model's performance is regenerated when `python -m app.export_model` is run. Prioritize macro F1, balanced accuracy, and Flop recall over accuracy alone. The holdout has only 8 Flop examples, so Flop recall is especially uncertain. Random splitting can also place names in both train and test and does not measure performance on entirely unseen people.
- The model predicts a category derived from IMDb score, not revenue, profitability, or audience preference.
- Some included input fields may not be available before release.
- The source CSV does not include poster images or plot synopses; the UI uses typographic tiles and only displays source metadata.
- Prediction probabilities are not calibrated.
